# Migration System — Milestone 2

**Purpose:** Migrate static JSON + assets → MySQL safely, repeatably, without modifying frontend.

**Files:**
- `config.example.php` — template, copy to `config.php` (gitignored) with real cPanel DB creds
- `migrate.php` — main CLI migration, PDO + prepared statements + transactions + idempotent ON DUPLICATE KEY UPDATE
- `README.md` — this file

---

## Architecture

```
database/
├── schema.sql (17 tables, InnoDB utf8mb4)
├── README.md (import instructions)
└── migrations/
    ├── config.example.php (template)
    ├── config.php (real creds, NOT committed, 600 perms, outside public_html ideally)
    ├── migrate.php (CLI only, PDO, transactions, idempotent)
    └── README.md
```

**Design Principles:**
- **CLI only:** `php_sapi_name() !== 'cli'` → 403, no public web endpoint
- **PDO + prepared statements:** No SQL injection, all queries prepared
- **Transactions per stage:** BEGIN → migrate stage → COMMIT, rollback on exception
- **Idempotent:** `INSERT ... ON DUPLICATE KEY UPDATE` + manual check for tables without UNIQUE on url/filename, DELETE + re-INSERT for M2M to avoid duplicates
- **Preserves slugs/IDs/content exactly:** No normalization of slugs, no shorten/rewrite of blog HTML, content hash verification
- **Validates source:** Checks file existence, JSON decode, required fields, slug regex `/^[a-z0-9-]+$/`
- **Reports errors clearly:** STDERR for errors, verbose log with timestamps, stats array, mapping report
- **Safe repeatable:** Can run twice, no duplicates (UNIQUE keys prevent, ON DUPLICATE handles)

## Idempotency Strategy

- **Tables with UNIQUE:** Use `INSERT ... ON DUPLICATE KEY UPDATE` — site_settings id=1, pages slug, services slug, projects slug, blog_categories slug/name, blog_tags slug/name, blog_posts slug/original_id, seo_settings page_type
- **Tables without UNIQUE on url/filename:** Manual check SELECT then UPDATE or INSERT — navigation_items (check url), media (check filename)
- **M2M / dependent:** DELETE existing for parent then INSERT — project_technologies, project_features, blog_post_tags (ensures no duplicates on re-run, preserves current state)
- **Result:** Safe to run twice, no duplicates, second run updates existing

---

## Rollback & Safety

- **Transactions:** Each stage BEGIN/COMMIT, ROLLBACK on exception, errors collected, script exits 1 on errors
- **No destructive DELETE:** Only DELETE for M2M clearing for idempotency within transaction, not for main content; no DELETE for site_settings, pages, services, projects, blog_posts, categories, tags, media
- **No source modification:** Never deletes content.json, blog_posts_real.json, assets, HTML, CSS, JS, build.py
- **Dry-run:** `--dry-run` flag validates source, counts, hashes, no DB writes
- **Static site untouched:** Migration only writes to DB, no HTML overwrite

## Usage

### Local with XAMPP / MAMP / Docker
```bash
cp database/migrations/config.example.php database/migrations/config.php
# edit config.php: db_host localhost, db_name portfolio, db_user root, db_pass ''
mysql -u root -p portfolio < database/schema.sql
php database/migrations/migrate.php
# or dry-run
php database/migrations/migrate.php --dry-run --verbose
```

### cPanel Production
1. cPanel → MySQL Databases → Create DB `portfolio` (actual `username_portfolio`) + User `portfolio_admin` + ALL PRIVILEGES
2. cPanel → phpMyAdmin → Select DB → Import → `database/schema.sql` → Go → Verify 17 tables
3. FTP: Upload `database/migrations/` to `/home/username/private/migrations/` (outside public_html)
4. Create `/home/username/private/config.php` from example with real creds, chmod 600
5. SSH or cPanel Terminal: `php /home/username/private/migrations/migrate.php`
6. Verify via phpMyAdmin counts
7. Delete migration folder after or keep private, ensure not web-accessible

### Security
- `config.php` gitignored, 600 perms, outside public_html ideally
- `migrate.php` CLI only check, no web access
- No secrets in JS, no API keys in repo
- Use strong DB password 20+ chars
